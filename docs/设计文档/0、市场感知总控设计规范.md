# 市场感知：总控系统设计规范 (Spec)

本文档定义了市场感知系统的“大合体”逻辑，涵盖了多模块解耦获取、定时更新、时间权限控制及统一文档归档的标准。

## 1. 统一归档结构 (Unified Output)
系统不再生成散乱的子报告，而是以日期为单位维护单一文件。

### 文件路径规范
- **元数据 (JSON)**: `tmp/data_cache/{YYYY-MM-DD}.json`
- **正式报告 (MD)**: `tmp/{YYYY-MM-DD}.md`

### 报告段落顺序 (Strict Order)
1. **一、 资金 & 情绪**
2. **二、 板块题材**
3. **三、 沪深创业科创偏好**
4. **四、 股价偏好**
5. **五、 市值偏好**

---

## 2. 模块级时间权限与渠道
每个模块根据数据时效性设定不同的获取窗口。

| 模块名称 | 盘中获取 (09:15-15:05) | 盘后获取 (15:05+) | 渠道策略 |
| :--- | :--- | :--- | :--- |
| **一、 资金情绪** | ✅ 允许 (实时) | ✅ 允许 (最终) | 盘中: direct, 盘后: skillhub |
| **二、 板块题材** | ✅ 允许 (实时) | ✅ 允许 (最终) | 盘中: direct, 盘后: skillhub |
| **三、 指数评分** | ❌ 禁止 | ✅ 允许 (最终) | 仅限盘后 (需要一年最高点对齐) |
| **四、 股价偏好** | ✅ 允许 (实时) | ✅ 允许 (最终) | 盘中: direct, 盘后: skillhub |
| **五、 市值偏好** | ✅ 允许 (实时) | ✅ 允许 (最终) | 盘中: direct, 盘后: skillhub |

---

## 3. 增量更新与幂等逻辑 (Incremental Logic)
脚本运行时需遵循以下伪代码逻辑：

1. **初始化环境**: 检查 `tmp/data_cache/` 目录。
2. **读取现状**: 如果 `tmp/data_cache/{date}.json` 存在，加载内容到内存。
3. **按模块调度**:
    - 遍历 1-5 模块。
    - **跳过逻辑**: 如果该模块在 JSON 中已标记为 `status: final` (盘后获取过)，则**跳过请求**。
    - **刷新逻辑**: 如果在盘中运行，无论是否有 `realtime` 缓存，均执行 API 覆盖。
4. **合并写入**:
    - **JSON**: 增量更新对应模块的 Key-Value，保留其他已存在模块的数据。
    - **MD**: 全量重写 MD 文件，确保 1-5 章节顺序固定。如果某个模块尚未获取，则在该章节下显示“> [待获取]”。

---

## 4. 语义复盘解耦
由于 Python 脚本主要负责“数算”，语义层面的“复盘”按以下标准处理：
- **占位符**: 脚本在 MD 中生成总结标题，内容默认为 `> [待复盘: 请指令 AI 填充此处]`。
- **人机交互**: 收盘后，用户指令 AI 执行“深度复盘”，由 AI 读取最新的 JSON 补全 MD 中的总结段落。
