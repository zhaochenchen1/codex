## 2. 数据获取与解析方案
该模块采用 **“类型强约束”** 问句策略，从源头上杜绝个股数据的混入。

### 2.1 强约束问句模板
执行 API 请求时，必须显式指定板块类型：

| 目标数据 | 推荐问句模板 | 目的 |
| :--- | :--- | :--- |
| **涨幅榜** | `{date} 概念板块涨幅前20` | 获取当日最火热题材 |
| **跌幅榜** | `{date} 行业板块涨跌幅排名从低到高` | 确保普涨日也能获取表现最弱板块 (取代"跌幅前20") |
| **流入榜** | `{date} 行业板块资金流入前10` | 排除个股，定位资金进攻行业 |
| **流出榜** | `{date} 行业板块资金流出前10` | 定位资金撤离行业 |

### 2.2 字段标准化 (Normalization)
解析返回数据时，必须执行 **“日期绑定优先策略”**，以确保提取的是目标日期的真实指标：

1.  **优先匹配**: 查找包含 `指标名[{date}]` 的列（如 `涨跌幅[20260513]`）。
2.  **次优匹配**: 查找包含 `指标名` 但排除 `最新` 字样的列。
3.  **兜底匹配**: 查找包含 `指标名` 的任意列。

| 标准列名 | 处理规范 |
| :--- | :--- |
| **板块名称** | 匹配 `指数简称` 或 `板块名称`，去空格。 |
| **涨跌幅** | 按日期绑定策略提取，强制格式化为 `+X.XX%`，忽略无效 NaN 值。 |
| **资金 (亿)** | 按日期绑定策略提取，统一折算并保留两位小数。 |

## 3. 数据质量管理 (Data Governance)
### 3.1 完整性标记
- **`complete`**: 1-4 小节数据均非空。
- **`partial`**: 缺失部分小节（如无资金流数据），MD 中对应表格需显示 `| [获取失败] | -- |`。

### 3.2 展示对齐要求
- MD 表格表头必须为中文业务列名（排名、板块名称、涨跌幅、流入资金）。
- 禁止在报告中直接输出原始 JSON Key (如 `name`, `val`)。

**注意事项**:
- **单位转换**: 资金流量必须从原始字节/元转换为“亿”单位。
- **额度优化**: 每日仅针对 target_date 运行一次，优先读取 `tmp/{date}.json` 缓存。
- **字段对齐**: Markdown 表格必须确保在不同长度的板块名称下依然对齐美观。
