## 2. 动态获取渠道方案
与“股价偏好”逻辑保持一致，根据时间窗口动态切换。

| 时间窗口 | 定义 | 获取渠道 | 缓存策略 |
| :--- | :--- | :--- | :--- |
| **盘中时间** | 交易日 09:15 - 15:05 | **pywencai Direct** | **强制实时获取**，标记为 `realtime` |
| **盘后时间** | 交易日 15:05 之后 | **SkillHub API** | **缓存优先**：若已存有 `status: final` 数据则不请求，标记为 `final` |

**问财 Query 模板 (分步请求策略)**:
- 区间 Q: `"{date}总市值在{low}到{high}亿之间的上涨股票数量，下跌股票数量"`
- 注意：为确保数据纯净，必须包含具体日期前缀。

## 3. 数据展示规范 (Formatting Standards)
为解决区间标签名漂移导致的显示异常（如出现 None），必须执行以下静态展示标准：

### 3.1 静态业务标签映射 (Static Label Mapping)
渲染 MD 报告时，必须直接使用下表定义的业务标签，禁止从 API 返回值中动态提取区间名：

| JSON Key | 业务标签 (MD 展示) |
| :--- | :--- |
| `b1` | (0, 10] 亿 |
| `b2` | (10, 50] 亿 |
| `b3` | (50, 100] 亿 |
| `b4` | (100, 300] 亿 |
| `b5` | (300, 1000] 亿 |
| `b6` | 1000 亿以上 |

### 3.2 标准五列制 (Strict 5-Column Table)
市值偏好表格必须包含以下 5 列：
1. **[市值区间 (亿)]**
2. **[上涨数量]**
3. **[下跌数量]**
4. **[上涨比例]**
5. **[下跌比例]** (计算公式：100% - 上涨比例)

### 3.3 审计与补全
- 必须确保 6 个区间的数据行全部存在，数据缺失时填充 `0` 和 `0.00%`。
- 百分比保留两位小数，金额逻辑同股价偏好模块。
