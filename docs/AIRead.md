# AI 任务执行规范与文档维护协议

> **最高指令：分层治理与最小化变更协议**
> 1. **第一层：展示优先 (MD -> JSON)**：当 MD 报告出现缺失或错误时，必须且仅能先从对应的日期 JSON 缓存中检索。严禁跳过 JSON 直接调取脚本。
> 2. **第二层：只跑不改 (JSON -> Script)**：若 JSON 中也无数据，则严格调用现有的单模块脚本进行获取。在此阶段，绝对禁止对脚本代码做任何一行修改。
> 3. **第三层：隔离沙盒 (Script -> Sandbox)**：若脚本获取失败，我必须：
>    - 1. 停下所有动作，反馈失败原因并提供解决思路。
>    - 2. 得到您的同意后，在 `code/test/` 目录下编写独立 Demo 脚本验证新逻辑。
>    - 3. 只有 Sandbox 验证通过且得到您的二次同意，才允许将代码同步回 `code/fill/` 的生产脚本。
> 4. **第四层：单点更新 (Sandbox -> JSON)**：脚本修正后，仅执行受影响的单点数据获取，并将结果增量更新至 JSON 缓存，严禁覆盖其他无关模块。
> 5. **第五层：外科手术式修复 (JSON -> MD)**：更新 MD 前，我必须向您明确：[更新章节]、[更新范围]、[具体数值]、[目标格式]。经您同意后，仅针对 MD 文件的特定标题块进行局部替换，绝对禁止重写或重置整个 MD 文档。

> **核心红线**：代码和执行严格隔离，绝对禁止边跑边改。

## 1. 核心运行逻辑
你现在处于一个具备“持久化记忆”的工作空间。每当你完成一次任务（脚本编写、API 调用、逻辑推理）后，必须执行【文档同步钩子】。

## 2. 文档同步钩子 (Hooks)
请在任务结束前，根据执行情况更新以下文件：

- **[docs/可用API.md]**: 
  - 触发条件：当 `curl` 或脚本调用成功返回数据时。
  - 记录内容：Endpoint、成功参数、返回示例、注意事项。
- **[docs/尝试失败的记录.md]**: 
  - 触发条件：报错、逻辑死循环、API 返回 4xx/5xx、或者方法虽可行但效率极低。
  - 记录内容：原始指令、失败报错信息、猜测原因、已排除的路径。
- **[docs/使用说明.md]**: 
  - 触发条件：新增文件、修改脚本启动参数、环境变量变动。
- **[docs/skill.md]**: 
  - 触发条件：运行 `iwencai-skillhub-cli install` 或手动注册新技能后。
- **[docs/gemini对话记录.md]**: 
  - 触发条件：当前对话首次开启或 ID 变更。
  - 记录内容：Session ID 以及一键恢复命令 (`gemini --session <id>`)。

## 3. 维护原则
- **增量更新**：严禁覆盖原有记录，使用 Markdown 的 `## [日期时间]` 格式进行追加。
- **结构化记录**：优先使用代码块和列表，确保信息“脱水”。
- **禁止废话**：记录必须直接、准确，以便于未来快速检索。
